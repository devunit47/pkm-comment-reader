# 配信デザイン・ローカル素材・CSSテーマ（Theme API 1）

## 使える機能と保存場所

Windowsローカル配布版・ローカル開発版のどちらでも、デザインエディタで配信デザイン・CSS・画像・雑談画面の配置を編集できます。適用した見た目（配信デザイン・CSS・雑談画面の配置・追加の文字と画像・出力の大きさ）は、アプリの`customization/current/`に保存します。接続先・音声・ユーザー管理・履歴の保持件数・初回案内・配信出力の背景は、`data/settings.json`に保存します。ブラウザ・ポート・OBSのドックで同じ設定を使い、変更をすぐ反映します。接続中の接続は切り替えません。ホームはウィンドウ幅に合わせた標準の配置を使います。

ローカル版だけは、次の専用フォルダーの素材をアプリ内の一覧から選べます。Windows配布版では`Start.cmd`、開発版では`package.json`と同じ場所に用意されます。

```text
アプリのフォルダー/
  style.css                標準の外観（直接編集しない）
  src/shared/theme.js      CSSの処理・編集例（直接編集しない）
  src/shared/studio.js     配信デザインの初期設定（直接編集しない）
  speech-background.svg    標準の読み上げ背景（直接編集しない）
  customization/
    styles/                利用者のCSS
    images/                利用者の画像
    current/               適用中の見た目（アプリが書き込む）
      design.json          見た目の設定
      images/              見た目が使う画像（内容のハッシュ名）
    presets/               名前付きのデザインプリセット
      <id>/
        design.json        全比率の配置・画像参照・CSSを含むデザイン
        images/            このプリセットが使う画像
```

専用フォルダーはローカル版で自動作成します。標準素材のコピーは入れません。標準素材をアプリ本体に残すことで、自分の素材を追加・入れ替えた後も標準の見た目へ戻せます。

## 保存形式と更新時の退避

今回から見た目はversion 3で保存します。version 2のcurrentとプリセットは従来の見た目・座標で読み込み、読むだけではファイルを書き換えません。新版で適用・保存、プリセットの新規保存・上書き・名前変更をしたときにversion 3になります。プリセットの確認だけでは元プリセットを変更しません。

更新前にアプリを終了し、`customization/`全体を別の場所へコピーしてください。少なくとも`current/`と`presets/`は、それぞれ`design.json`と`images/`を含むフォルダーごと退避します。「設定のバックアップ」には見た目と画像が入りません。

**新版で保存したcurrent・プリセットをv0.3.0以前で開かないでください。** 操作画面を開くだけでも、最終更新から24時間を超えたcurrent画像が自動整理で削除される場合があります。設定変更や標準復帰では、version 3の原本が標準のversion 2で上書きされます。

古い版へ戻す場合は**v0.3.1以降**を使ってください。この版以降は、読めない原本の上書きとcurrent画像の整理を止め、読めないプリセットの画像も保持します。ただし、version 3に対応しない版では標準表示と理由の案内になり、version 3の見た目は表示・編集できません。新版の保存先を使わず、退避したversion 2のフォルダーを旧版と組み合わせてください。`design.json`のversionだけを2に変更しても、画像配置の互換性は戻りません。

## デザインのプリセット

「配信デザイン」の先頭で、今の見た目を名前付きのプリセットに保存できます。配信デザイン・テーマCSS・立ち絵・読み上げ背景・16:9／9:16／4:3の配置と追加の文字・画像・出力の大きさを、`customization/presets/<id>/`にまとめて保存します。配信出力の背景モード・クロマキー色、接続先・音声・ユーザー管理・コメント履歴は含みません。

- 「今のデザインを保存」で名前を入れて新規保存します。名前は前後の空白を除いて1〜40文字（絵文字や結合文字も1文字として数えます）。改行・制御文字は使えません。同じ名前でも保存でき、更新日時とidで区別します
- プリセットを選んで「読み込む」を押すと、エディタの「プリセットを確認」を開きます。比率・確認サイズ・隠れやすい範囲の表示だけを切り替えて確認し、「適用」の確認後にデザイン全体を置き換えます。編集の道具や素材選択は表示しません。適用前は今のデザイン・配信出力を変えません。「キャンセル」やEscで閉じると元のままです
- 「上書き保存」は選んだプリセットを今のデザインで置き換えます。「名前を変える」は名前だけを変更します。「削除」は確認後に選んだプリセットのフォルダーを削除します
- 「標準へ戻す」は確認後に今のデザイン全体（全比率・画像・CSS・出力の大きさ）を組み込み標準へ戻します。保存したプリセットは残ります
- フォルダーを手で追加・変更したら「一覧を更新」を押します。読めないプリセットは理由付きで表示し、選べません。画像はPNG・JPEG・WebP・GIF、1枚20MiB・1600万画素以内で、内容のSHA-256と一致するファイル名が必要です
- 「フォルダーを開く」で、選んだプリセットのフォルダー（未選択なら`presets/`）をWindowsのエクスプローラーで開きます。ほかのOSでは場所を表示します

見た目を別の環境へ移すときは、プリセットのidフォルダーを`design.json`と`images/`ごとコピーし、移した先で一覧を更新してください。idは小文字英数字・ハイフンで1〜64文字です（Windowsの予約名は使えません）。フォルダー内のシンボリックリンク・ジャンクションは読み込みません。

標準へ戻す・適用で今のデザインから参照されなくなった画像は、その時点から24時間保護し、期限後の保存や一覧更新で片付けます。上書きでプリセットから外れた画像も24時間保護し、期限後の一覧更新・上書き・名前変更で片付けます。プリセットの削除ではフォルダーと画像をすぐ消します。削除に失敗して残った内部の退避フォルダーは、次の一覧更新などで消します。適用中のデザインは画像のコピーを持つので、プリセットを削除しても変わりません。

適用すると、開いている別のタブや配信出力にも見た目が反映します。確認中に別の画面でデザインが変わった場合は、古い下書きの適用を止めます。キャンセルして読み直してください。

## デザインエディタと追加の文字・画像

配信デザインページまたは雑談画面の「デザインを編集」で開くデザインエディタは、雑談画面のコピーを見ながら見た目を1つの下書きで編集する全画面の編集画面です。雑談画面から開いた場合は、適用・閉じるのあとに雑談画面へ戻ります。左の対象一覧で「画面全体」・ヘッダー・コメント欄・読み上げ・立ち絵・フッター・追加した文字と画像を選ぶと、右にその対象の設定だけを表示します。狭いウィンドウやOBSのドックでは、キャンバスの下で「対象」「設定」を切り替えます。

雑談画面の操作ボタンは、右上の操作領域にマウスを重ねるか、ボタンにフォーカスすると表示します。雑談画面にフォーカスを移してマウスを操作領域の外へ動かすと隠れ、タッチ操作では常時表示します。幅150px程度でも操作できるよう、狭い幅ではボタンを比率の枠の外に重ねて表示します。画面収録前に操作ボタンが隠れたことを確認してください。

プレビューはサンプルコメントを表示し、チャットへの接続・音声再生は行いません。素材の一覧と読み込みはエディタの選択欄で行います。外部フォントも読み込まないため、端末標準フォントで代用される場合があります。文字の折り返しや幅は適用後の実表示でも確認してください。接続先・音声設定・コメント保持数は変えません。

- 編集はすべての比率をまとめた下書きです。「適用」を押すと`design.json`へ1回で保存し、配信画面・配信出力へ反映します。それまでは元の雑談画面と保存内容を変更しません
- 「変更をすべて破棄」は、この編集での変更をすべての比率で取り消し、エディタを開いたまま編集を始めたときの内容に戻します
- 変更があるときに「閉じる」・Escapeを押すと、下書きを破棄して閉じるか確認します
- 「取り消し」「やり直し」（Ctrl+Z、Ctrl+Shift+ZまたはCtrl+Y）で、1操作ずつ戻したり進めたりできます。ドラッグ1回、続けて入力した文字、押し続けた矢印キーはそれぞれ1操作です。別の比率の操作を取り消すと、その比率を表示します。文字や数値を入力している間のCtrl+Zは、入力欄の取り消しになります。履歴は100操作までで、適用・破棄・閉じると消えます
- 「デザイン全体を標準に戻す」は、確認のうえ、出力の大きさ・テーマCSS・すべての比率の配置と追加の文字・画像・立ち絵画像の配置を含む標準のデザインを下書きに読み込みます。適用するまでは保存しません
- 変更があるままページを再読み込みしたりタブを閉じたりすると、ブラウザの確認が表示されます
- 編集中に別の画面でデザインが保存されると、古い下書きは適用できなくなります。「最新のデザインからやり直す」で最新の内容から編集し直してください
- 数値欄を空にして確定すると、直前の値のまま変わりません

- 「文字を追加」または画像ファイル選択で、最大20個の項目を追加します
- 文章は改行を含む1000文字まで、文字サイズは12〜160px、色を個別に設定できます
- 選択枠の内側のドラッグで移動、辺・角の8個のハンドルでサイズを変更します。右欄の数値でも調整でき、位置とサイズは%で保存します
- パネルの右辺・下辺を広げるときは、左辺・上辺を保って画面端で止めます。吸着や小数の座標を使う場合も同じで、幅・高さの数値が大きすぎても位置を動かさずにサイズを抑えます
- 読み上げ枠が最小高さで補正されているときは、ドラッグ・キー操作を表示中の位置と大きさから始めます。動かしていない方向の保存値は保ち、確認サイズの変更だけでは配置を変えません
- 重なり順は0〜99で、数値が大きいほど手前に出ます。同じ数値ならヘッダー→コメント欄→読み上げ→立ち絵→フッター→追加要素の並び順に手前になります。「前へ」「後ろへ」でパネルと追加要素の表示順を1つずつ入れ替えます。テーマCSSが独自の重なりの基準を作る場合、この順序は保証しません
- 横長の標準の並び（16:9・4:3）のパネルは重なり順0です。重なり順0や1の追加要素は従来どおりパネルの手前に出ます。最初の配置変更で標準の並びを数値化した場合も、この順序を保ちます
- 項目を選んで削除・非表示にできます。どこからも使われなくなった画像ファイルは、24時間たってから次の保存のときに`customization/current/images/`から片付けます（編集中の下書きの画像を消さないため）。PCの元ファイルは削除しません
- 画像はPNG・JPEG・WebP・GIFのみ。1枚20MiB・1600万画素以内で、合計の上限はありません。画像の内容と実際にデコードできることを確認します。SVG・HTML・外部画像URLには対応しません
- 「編集する比率」で16:9・9:16・4:3を選びます。「確認サイズ」は同じ比率のサイズだけを表示します。サイズは1920×1080・1280×720・960×540・640×360（16:9）、1080×1920（9:16）、1440×1080（4:3）から選べます。編集画面に収まるように縮小表示しますが、保存される割合座標は変更しません。縦長は高さに合わせて縮小します
- 追加の文字・画像は比率ごとに別々に保存します。「編集する比率」を変えると、その比率の配置と追加項目を表示・編集します。確認サイズだけを変えても保存座標と出力サイズは変わりません。適用すると、変更したすべての比率をまとめて保存します
- 9:16では「アプリで隠れやすい範囲を表示」で、上6%・下10%（縦型の配信アプリでボタンや説明文が重なりやすい範囲）を斜線で表示します。16:9と4:3は配信で画面の端が切れないため、ガイドはありません。表示はプレビューだけで、雑談画面・配信出力には映りません
- 「適用」は検証と保存が成功してから本来の画面に反映します。設定・CSS・追加項目は design.json 1つにまとめて書くので、一部だけが保存されることはありません。保存に失敗したら編集画面を残します

出力の大きさも「画面全体」で下書きとして編集します。配信出力（OBS用）欄では適用中の大きさを表示し、「エディタで変更」で開けます。背景・クロマキー色は出力欄で変更します。追加項目は雑談画面のみが対象で、ホームの既存パネルには追加しません。通常の雑談画面では追加項目はクリック操作を受け取らず、接続ボタンなどを操作できます。

画像は選んだ時点で同じPCのローカルサーバーへ送り、`customization/current/images/`に保存します（インターネットには送りません）。追加項目と画像は、適用したときに見た目の一部になります。以前あった「文字・画像セット」「見た目と配置」「配置」のファイル書き出し・読み込みは廃止しました。見た目を別の環境へ移すときはプリセットに保存し、idフォルダーごとコピーしてください。

保存した見た目は、開いている別のタブ・配信出力・OBSのブラウザソースにすぐ反映します。編集画面を開いている間に別の画面で見た目が保存された場合は、古い下書きで上書きしないよう「適用」を止めます。キャンセルして開き直すと、新しい見た目から編集できます。ウィンドウキャプチャ／画面収録では編集画面自体が映るため、別シーンなどで編集し、配信に出す前にOBS側の実表示を確認してください。画像や文字を読み上げ枠の上に重ねると音声クレジットも隠れる場合があります。

## Twitchコメントの表示

デザインエディタの「コメント欄」で、次の見た目を下書きで試し、「適用」で保存します。雑談画面・プレビュー・配信出力で共用し、操作画面のコメント一覧とKickは従来どおり文字で表示します。

- 名前の色：「テーマのまま」（初期値）・「サービスの色」・「色を指定」。「サービスの色」はTwitchの投稿者の色を使い、色がなければテーマの色です。投稿ごとの背景、またはパネル背景を白・黒にした場合だけ、背景とのコントラスト比が3:1以上になるよう補正します。背景がテーマのまま・なしの場合は補正しません
- エモート：「画像で表示」（初期値）・「文字のまま」。画像はTwitchのCDNから取得し、動くエモートは動いたまま表示します。高さは本文の約2倍で、横幅は画像の比率を保ちます。行の中央にそろえて上下の余白を調整し、行間の広がりを抑えます。読めない画像はエモート名に戻します。「文字のまま」では画像を取得しません
- 役割バッジ：初期値は非表示です。オンにすると、配信者・モデレーター・VIP・サブスクの記号4種だけを名前の前に表示します。チャンネル独自のバッジ画像やサブスク月数は表示しません

エモートは表示方法にかかわらず読み上げません。エモートだけの投稿は、名前を読む設定でも読み上げません。検索・ユーザー管理・コメントの確認には元の本文を使います。設定は`customization/current/design.json`に保存し、コメント欄のプリセットを切り替えてもエモートとバッジの設定を保持します。

## 配信出力の表示件数と表示時間

デザインエディタの「コメント欄」で、配信出力に出す件数（標準は制限なし、または1～30件）、表示時間（時間では消さない／5／15／30秒）、新着位置（下／上）を設定できます。表示時間は操作画面の受信時刻から数えます。出力を開き直しても期限は延びません。雑談画面の履歴・ユーザー管理・読み上げは残り、制限を緩めると保持中の履歴から条件に合う投稿が再表示されます。履歴件数より多くは出せず、枠に収まる件数は文字と枠の大きさにも依存します。デザインプレビューは10件のサンプルで件数と新着位置を確認でき、サンプルには名前の色・役割バッジ・画像エモートを含み、表示件数を1件にしても試せます。サンプルは時間で消えません。

## ローカルフォルダーの素材を使う

1. OSのファイル管理画面で、素材を`customization/styles/`または`customization/images/`へコピーします。
2. デザインエディタを開き、「customizationフォルダーから選ぶ」で「一覧を更新」を押します。CSSは「画面全体」→「詳細：テーマCSS」、画像は「立ち絵」「読み上げ」または道具の「画像を追加」から選べます。
3. 素材を選び、「下書きに読み込む」を押します。候補を切り替えただけでは読み込みを始めず、進行中のPCファイル・フォルダー素材の読み込みも取り消しません。CSSは下書きのテーマCSS、画像は立ち絵・名前とコメントの背景・追加画像として使います。読み込み中は適用できません。
4. プレビューで確認し、エディタの「適用」でまとめて保存します。選択しただけでは配信画面に反映しません。

| 素材 | フォルダー | 対応形式と上限 |
| --- | --- | --- |
| CSS | `customization/styles/` | UTF-8の`.css`、1,000,000バイト以内 |
| 立ち絵・読み上げ背景・追加画像 | `customization/images/` | `.png`・`.jpg`・`.jpeg`・`.webp`・`.gif`、各20,971,520バイト以内（20MiB）・1600万画素以内 |

対象は各フォルダーの直下にある通常のファイルだけです。サブフォルダーを検索せず、シンボリックリンクも読み込みません。SVG・HTMLや任意のファイルは読み込み対象ではありません。画像はブラウザで読み込めることを確認してから適用します。隠しファイル、Windowsで使用できない名前（例：`CON.css`）、末尾が空白やピリオドの名前も対象外です。CSSは手動入力・ファイル読み込みと同じ検証を行い、[CSSの公開契約](#cssの公開契約)の範囲でだけ適用します。

ファイルを追加・名前変更・編集した場合は一覧を更新し、必要な素材を選んで適用し直してください。自動監視・自動反映はしません。アプリの画面からフォルダー内のファイルを作成・編集・削除する機能はありません。

### 素材のコピーと見た目の適用

画像は選んだ時点で検査して`customization/current/images/`にコピーし、下書きには画像参照を入れます。CSS本文と画像を使う見た目は「適用」で`customization/current/design.json`へまとめて保存します。素材のファイルパスを保存して毎回読み直す方式ではありません。

- ブラウザやポートを変えても、同じアプリのフォルダーなら同じ見た目になります
- 元ファイルを編集しても、適用済みの内容は変わりません。一覧更新後に再適用してください
- 元ファイルを移動・削除しても、適用済みの内容は残ります
- 保存できない場合（フォルダーの権限など）はエラーを表示し、見た目は変わりません

`styles/`・`images/`は元ファイルの置き場で、アプリは書き換えません。アプリが書き込むのは`current/`と`presets/`です。新しいローカル配布版へ更新する場合も、自分の`customization/`と`data/`を新しい版の同じ場所へコピーします。アプリ本体の標準ファイルは新しい版のものを使ってください。

## 音声クレジットの表示

ローカル版でVOICEVOX・COEIROINKを選ぶと、ホームのプレビューと雑談画面の読み上げ枠に、選択した声のクレジットを自動表示します。パネル・吹き出し・画像の各スタイルで表示し、読み上げ本文のスクロール領域とは別に配置します。読み上げ枠を非表示にしたり、極端に小さくしたり、別の枠を重ねるとクレジットも映らない場合があります。配信前にOBS側でも確認してください。見た目のリセットでは音声設定を変えず、クレジット表示も選択した声を引き継ぎます。各音声の追加条件は[READMEの読み上げ案内](../README.md)と音声側の利用規約を確認してください。

## エディタで雑談画面の配置を変える

「配信デザイン」の「デザインを編集」で、5パネルと追加の文字・画像を同じキャンバスで配置します。変更は下書きに入り、「適用」まで保存しません。

- キャンバスでは一番手前の対象を選びます。背後や非表示の対象は左の一覧から選べます。非表示の対象は選択中だけ輪郭を表示し、右欄で表示に戻せます
- プレビューがスクロールしているときも、非表示の対象の輪郭は表示中の対象と同じ位置を基準にします
- 位置・サイズ・重なり順・非表示は右欄の「この比率の配置」で調整します。標準配置は、最初に配置を変更したときだけ数値の配置に変わります
- 吸着は標準でONで、ドラッグを2%単位にそろえます。Altを押している間は一時解除します。数値入力は吸着せず小数も使えます
- 選択枠にフォーカスがあるとき、矢印キーで移動（吸着ONは2%、OFFは1%）、Shift＋矢印でサイズ変更、Deleteで追加要素だけを削除します。ドラッグ中のEscapeはその操作だけを取り消します
- 追加画像の角をShiftを押しながらドラッグすると縦横比を保ちます。画面外のハンドルは周囲の作業余白にも表示し、一覧と数値から画面内へ戻せます。余白や編集用の枠は配信に映りません
- 16:9・9:16・4:3の配置は独立しています。未作成の比率はその比率の標準を使い、ほかの比率の配置を自動で使いません
- 「画面全体」の「別の比率からコピー」は、確認後、編集中の比率のパネル配置・追加要素・立ち絵画像の配置を置き換えます。コピー元が横長の標準配置なら、パネル配置を残して追加要素と立ち絵画像の配置だけを写します。見た目・CSS・出力サイズは変えません
- 「この比率の配置を標準に戻す」は、確認後、この比率の5パネルと立ち絵画像の配置だけを戻します。追加要素・共通の見た目・別比率は残ります。コピーも標準化も取り消し1回で戻せます

雑談モードは、適用済みの「出力の大きさ」の幅・高さで描き、完成画面全体を窓の中央に収めます。小さな窓では縮小し、出力の大きさより大きな窓では窓いっぱいまで拡大します。余った部分は暗い背景になります。文字・画像・余白も一緒に拡大・縮小し、窓のリサイズでは保存座標や出力サイズを変更しません。デザインプレビューと比べるときは、確認サイズを適用済みの出力サイズにそろえ、表示内容とフォント条件も同じにしてください。配信出力は従来どおり実際の窓の大きさで描き、自分の大きさにいちばん近い比率の配置を使います。

終了・自動読み上げ・デザイン編集・接続・サービス切り替え・音量は、完成画面に重ねた右上の操作領域にあります。ボタンとダイアログは完成画面と一緒に拡大・縮小しません。操作領域へマウスを重ねるか、ボタンにフォーカスすると表示し、タッチ環境では常時表示します。狭い幅では操作領域が折り返し、領域内のスクロールですべての操作へ移動できます。

## ホームの配置

ホームのコメント一覧・読み上げプレビュー・読み上げ設定は、ウィンドウ幅に合わせた標準の配置で表示します。保存済みのホームの自由配置は読み込まず、新しい設定バックアップにも入れません。接続設定やユーザー一覧の専用ページは従来の配置を使います。テーマCSSは専用ページやサイドバーにも適用できます。

## 立ち絵画像と追加画像の配置

デザインエディタの対象一覧で「立ち絵」を選び、「この比率の立ち絵画像の配置」で調整します。「編集する比率」が編集対象です。画像ファイルもエディタの「立ち絵」で選びます。パネルの大きさと画像の拡大率は別々に調整できます。

- 「テーマのまま」ではテーマCSSの画像配置を使います。「自分で調整」では拡大率100〜200%、左右・上下の位置合わせ、枠の寸法に対する±100%の微調整、枠からのはみ出しを設定できます。
- 「下」は透過余白を含む画像ファイルの下端です。人物の足元を合わせるには微調整を使ってください。枠・キャプション・飾りは拡大しません。
- 「テーマのまま」に戻しても調整値を保持し、再び「自分で調整」にすると以前の値を使います。画像なし・空き枠でも値は保持しますが描画しません。
- 16:9・9:16・4:3は独立しています。変更は「適用」で全比率をまとめて保存し、下書きを破棄して閉じても保存しません。「この比率の配置を標準に戻す」はこの比率のパネルと立ち絵画像の配置を戻します。「デザイン全体を標準に戻す」は全比率を含めて戻します。

追加画像の幅・高さは2〜200%、各辺へ画面1枚分まではみ出せます。画像の枠を画面内に幅・高さ各2%残すよう補正し、画面の境界で切り取ります。透過部分だけが画面に残る場合や選択枠が外へ出た場合も、「編集する対象」から選び、数値で戻せます。文字と既存パネルの範囲は従来どおりです。

## CSSの公開契約

デザインエディタの立ち絵の枠・背景・キャプション、投稿ごとの背景、本文の最大行数は、「テーマのまま」なら属性・変数を追加せず、テーマCSSを使います。明示した設定はテーマCSSの`!important`より優先します。「制限なし」はCSSの本文行数制限を解除します。行数制限は表示だけに適用し、本文のデータと読み上げは切りません。

コメント文字サイズは互換性のため、従来どおりテーマCSSで上書きできます。設定可能な範囲は16〜64px、標準は20pxです。「丸いチップ（本文2行）」は投稿ごとの白い背景・不透明度92%・本文2行・投稿間隔14pxをまとめて指定しますが、文字サイズ・配置・表示件数は変えません。

デザインエディタの「画面全体」→「詳細：テーマCSS」で編集し、「適用」で保存します。CSSファイルの読み込み・解除・編集中のCSSの書き出しにも対応します。入力したCSSにエラーがあるあいだは、最後に有効だったCSSでプレビューし、適用できません。CSSファイルや画像を読み込んでいるあいだも、読み込みが終わるまで適用できません。
Theme API 1のセレクターは次のとおりです。

| セレクター | 対象 |
| --- | --- |
| `.pokome-workspace` | 操作画面、サイドバー、ホームの配置領域、雑談画面 |
| `.pokome-panel[data-panel-type="comments"]` | ホームのコメント一覧 |
| `.pokome-panel[data-panel-type="now"]` | 読み上げプレビュー |
| `.pokome-panel[data-panel-type="reading"]` | 読み上げ設定 |
| `.pokome-panel[data-panel-type="moderation"]` | ユーザー管理 |
| `.pokome-panel[data-panel-type="header"]` | 雑談画面のタイトル・ひとこと |
| `.pokome-panel[data-panel-type="chat"]` | 雑談画面のコメント一覧 |
| `.pokome-panel[data-panel-type="speech"]` | 雑談画面の読み上げ |
| `.pokome-panel[data-panel-type="actor"]` | 立ち絵・ワイプ |
| `.pokome-panel[data-panel-type="footer"]` | 雑談画面のフッター |
| `.pokome-comment` | コメント1件 |
| `.pokome-comment__author` | コメントのユーザー名 |
| `.pokome-comment__body` | コメント本文 |

全セレクターは `.pokome-workspace` またはその子孫を指定してください。
通常ルールと `@media`、`@supports` に対応します。ネストした通常ルールは展開してください。雑談画面の`vw`・`dvh`・`@media`は適用済みの出力サイズを基準にするため、操作用の窓を小さくしても文字の折り返しや配置は変わりません。プレビューでは選んだ確認サイズが基準になります。
外部URL、画像URL、`@import`、`@font-face`、キーフレームはこの版では対応しません。
CSS本文はUTF-8で1,000,000バイトまでです。手動の読み込みファイル・ローカルフォルダーから選ぶCSSファイルも同じ上限です。ブラウザが解釈できない宣言は適用されません。

```css
/* Pokome Theme API: 1 */
.pokome-workspace {
  --pk-font-family: sans-serif;
  --pk-accent-color: #ffd19a;
}
.pokome-workspace .pokome-panel {
  background: #20232b;
  border: 1px solid #ffd19a;
  border-radius: 8px;
  color: #fff;
}
.pokome-workspace .pokome-comment__body {
  line-height: 1.6;
}
```

`--pk-font-family`、`--pk-text-color`、`--pk-accent-color`を提供します。
詳細な外観は公開セレクターに直接指定できます。雑談画面の位置・サイズはデザインエディタで管理します。
既存のテーマや配信デザイン設定の上にCSSを適用します。
例外として、デザインエディタの「コメント欄」で「テーマのまま」以外を選んだ項目（パネルの背景、本文・名前の色、縁取り、行間、間隔、区切り線、見出し）は、その設定が優先されます。CSSに`!important`を付けた指定よりも優先します。パネルの背景を白・黒にすると、文字の色が「テーマのまま」でもパネルに合った読みやすい色を使います。コメント欄をCSSで細かく指定する場合は、その項目を「テーマのまま」に戻してください。
エディタの操作欄はテーマの影響を受けない独立した領域に表示されます。
雑談画面はEscapeキーでも終了できます。

## 標準に戻す

- CSSだけを戻す：デザインエディタの「CSSを解除」で下書きのCSSを空にし、「適用」で保存します。配信デザインの設定・画像・配置はそのままです
- 立ち絵だけを外す：「画像を削除」で登録画像を外します。表示方法の選択は保持するため、OBS用の空き枠として使う場合は「表示するもの」も「空き枠 / OBSで映像を重ねる」に切り替えてください。標準の立ち絵画像は同梱していません
- 読み上げ背景だけを戻す：「標準の背景画像に戻す」で、同梱の吹き出し背景へ戻せます
- 配置だけを戻す：エディタの「この比率の配置を標準に戻す」で、編集中の比率の5パネルと立ち絵画像の配置を下書きに戻し、「適用」で保存します
- 見た目全体を戻す：操作画面の右下にある「見た目を標準に戻す」を押し、確認画面で「標準に戻す」を押します。CSS・立ち絵・読み上げ背景・配信デザインの設定（色・文字・配信タイトルなど）・全比率の雑談画面の配置と追加の文字・画像・出力の大きさを初期状態へ戻し、立ち絵の表示方法も標準の空き枠になります。接続先・音声・ユーザー管理設定は保持します。開いていたエディタの下書きは保持しますが、適用できなくなります。「最新のデザインからやり直す」で標準の内容から編集し直せます。確認画面の「キャンセル」では何も変更しません

見た目全体のリセット操作は追加CSSの影響を受けない領域にあります。雑談モードでは表示しないため、「雑談モードを終了」またはEscapeキーで操作画面に戻ってから使ってください。どのリセットも`styles/`・`images/`の元ファイルを削除・上書きしません。適用中の見た目を残したい場合は、リセット前に`customization/current/`をコピーしてください。

### design.jsonを読めないとき

JSONの書き間違いや対応していない形式・バージョンで`customization/current/design.json`を読めない場合は、理由を表示して標準の見た目で開きます。原本と画像を保護するため、見た目の保存・標準復帰・プリセット適用・今のデザインからのプリセット保存を止め、`current/images/`の古い画像も片付けません。読めないプリセットも読み込み不可として表示し、その画像を片付けません。

アプリを終了し、`customization/current/`を`design.json`と`images/`ごと別の場所へコピーしてから、JSONを修正するか、その保存形式に対応する版で開き直してください。標準で始め直す場合は、退避が完了したことを確かめてから元の`current/`を保存先の外へ移し、アプリを起動します。読めない原本を画面から強制的に上書きする操作はありません。「設定のバックアップ」には見た目と画像が入らないため、フォルダーのコピーが必要です。

## 保存と共有

適用中の見た目は`customization/current/design.json`に保存します。画像は同じフォルダーの`images/`に、内容のSHA-256をファイル名にして保存します。

```json
{
  "format": "pokome-design",
  "version": 3,
  "name": "",
  "theme": ".pokome-workspace { --pk-accent-color: gold; }",
  "studio": { "theme": "mint", "image": "images/<64桁のハッシュ>.png", "…": "…" },
  "outputSize": "1280x720",
  "ratios": { "16:9": { "layout": null, "overlays": { "version": 1, "items": [], "assets": {} } }, "9:16": null, "4:3": null }
}
```

- 読み込むときは毎回すべての値を検査し、範囲外の値は捨てるか標準値にします。画像は`images/<ハッシュ>.<拡張子>`の形で、ファイルの中身とハッシュが一致し、形式・大きさ・画素数の検査に通ったものだけを使います
- 配置の`null`は初期配置です。自由配置では`panels`に全パネルの`x`, `y`, `w`, `h`, `z`, `hidden`を保存します。位置・サイズは画面内に収め、幅・高さは5〜100%、重なり順は0〜99に制限します
- `ratios`は画面の比率ごとの配置と追加項目です。`null`は「まだ作っていない」で、その比率の標準を使います。9:16の`layout: null`は縦用の標準配置です
- テーマCSSは保存のたびではなく、表示するたびに[CSSの公開契約](#cssの公開契約)で検査します

見た目以外の設定は`data/settings.json`（version 2）に保存し、「設定のバックアップ」も同じ形式で書き出します。旧版のversion 1も復元でき、含まれていない初回案内と配信出力の背景は標準に戻します。古い見た目・画像・配置は無視します。更新前のブラウザ設定は自動では移しません。更新前に旧版のバックアップを保存し、新版で復元してください。`data/`には接続先・ユーザー名が含まれるため、人に渡さないでください。読めないsettings.jsonは既定値で開き、保存を止めて案内します。アプリを終了してdata/を退避し、JSONを修正するか、原本を保存先の外へ移してから開き直してください。

見た目を別の環境へ移す・人に渡すときは、プリセットに保存して`customization/presets/<id>/`をコピーしてください。design.jsonには接続先・コメント履歴・ユーザー管理データは入りません。CSSだけを渡す場合はエディタの「編集中のCSSを書き出す」も使えます。

ブラウザCSSOM・画面操作の検証テストはPlaywrightと対応ブラウザを使います。インストール済みのPlaywrightと、同梱ブラウザまたはLinux／Windowsの対応ブラウザを自動検出します。必要に応じて`PLAYWRIGHT_MODULE`にPlaywrightモジュールのパス、`BROWSER_EXECUTABLE`にブラウザの実行ファイルを指定できます。利用できる環境が見つからない場合はブラウザを使うテストをスキップします。

ブラウザの起動が実行環境の制限で禁止されている場合は、`SKIP_BROWSER_TESTS=1`でサーバー・モデルのテストだけを実行できます。これは画面検証の合格を意味しません。対応環境でブラウザテストを別途実行してください。

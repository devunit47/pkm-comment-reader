# 配信デザイン・ローカル素材・CSSテーマ（Theme API 1）

## 使える機能と保存場所

GitHub Pages版・Windowsローカル配布版・ローカル開発版のどれでも、配信デザイン、自由配置、CSSの編集／ファイル読み込み、立ち絵・読み上げ背景のファイル読み込みを使えます。適用した内容はブラウザに保存します。GitHub Pages版でもファイル選択画面で手元の素材を選べますが、PCのフォルダーを一覧表示することはできません。

ローカル版だけは、次の専用フォルダーの素材をアプリ内の一覧から選べます。Windows配布版では`Start.cmd`、開発版では`package.json`と同じ場所に用意されます。

```text
アプリのフォルダー/
  style.css                標準の外観（直接編集しない）
  theme.js                 CSSの処理・編集例（直接編集しない）
  studio.js                配信デザインの初期設定（直接編集しない）
  speech-background.svg    標準の読み上げ背景（直接編集しない）
  customization/
    styles/                利用者のCSS
    images/                利用者の画像
```

専用フォルダーはローカル版で自動作成します。標準素材のコピーは入れません。標準素材をアプリ本体に残すことで、自分の素材を追加・入れ替えた後も標準の見た目へ戻せます。GitHub Pagesの公開ファイルには`customization/`とその中身を含めません。

## 追加の文字・画像とデザインプレビュー

「プレビューでデザインを編集」は、雑談画面のコピーで見た目を試すための専用編集画面です。プレビューはサンプルコメントを表示し、チャットへの接続・音声再生・ローカル素材APIの呼び出しは行いません。外部フォントも読み込まないため、端末標準フォントで代用される場合があります。文字の折り返しや幅は適用後の実表示でも確認してください。配信デザインの配色・文章・文字サイズ・読み上げ枠の見た目・CSSと追加項目だけを編集し、接続先・音声設定・コメント保持数は変えません。元の雑談画面と設定保存先は「適用する」まで変更しません。

- 「文字を追加」または画像ファイル選択で、最大20個の項目を追加します
- 文章は改行を含む1000文字まで、文字サイズは12〜160px、色を個別に設定できます
- 「移動」「大きさ」のドラッグ、矢印キー、Shift＋矢印キー、数値入力で位置・サイズを調整します。位置とサイズは%で保存します
- 重なり順は0〜99で、数値が大きいほど手前に出ます。同じ数値なら後から追加した項目が手前です。既存の枠の重なり順とも組み合わせられます
- 項目を選んで削除・非表示にできます。削除後にどの項目からも使われなくなった画像は、適用時にブラウザ内の追加素材から取り除きます。PCの元ファイルは削除しません
- 画像はPNG・JPEG・WebP・GIFのみ。1枚512KiB、追加画像の合計2MiB、1600万画素以内です。画像の内容と実際にデコードできることを確認します。SVG・HTML・外部画像URLには対応しません
- 1280×720・960×540・640×360の論理画面サイズで確認できます。編集画面の横幅に合わせて縮小表示しますが、保存される割合座標は変更しません
- 「適用する」は検証と保存が成功してから本来の画面に反映します。保存に失敗したら編集画面を残し、変更した設定の書き戻しを試みます。書き戻しも失敗した場合は警告します
- 「キャンセル」、Esc、戻る／進む操作で未適用の変更を捨てます。プレビュー内の標準化ボタンも、適用までは元の見た目を保持します。既存の枠の配置はこのボタンではリセットしません

従来の「画面の配置」、デザイン設定、CSSの適用、ローカル素材一覧は引き続き即時反映です。追加項目は雑談画面のみが対象で、ホームの既存パネルには追加しません。通常の雑談画面では追加項目はクリック操作を受け取らず、接続ボタンなどを操作できます。

画像はサーバーへアップロードせず、適用時にこのブラウザの専用設定へ保存します。「文字・画像セットを保存／読み込み」で追加項目だけを移行できます（JSON、3MiB以内）。読み込みはプレビュー内だけを置き換えます。「設定のバックアップ」には追加項目も含まれ、旧版のバックアップも読み込めます。従来の100KB配置ファイル・200KB見た目ファイル・CSSファイルに追加画像を埋め込まないため、それらのファイルだけでは追加項目は移行しません。

同一ブラウザプロファイル・同一オリジンでの再読み込みには保存内容を引き継ぎますが、別タブへのリアルタイム同期は行いません。別のタブで保存が変わった場合は編集・適用を止め、ページの再読み込みを案内します。OBSのブラウザソースは一般のブラウザと保存先が異なる場合があります。ウィンドウキャプチャ／画面収録では編集画面自体が映るため、別シーンなどで編集し、配信に出す前にOBS側の実表示を確認してください。画像や文字を読み上げ枠の上に重ねると音声クレジットも隠れる場合があります。

## 配信出力の表示件数と表示時間

配信デザインの「コメント一覧」で、配信出力に出す件数（標準は制限なし、または1～30件）、表示時間（時間では消さない／5／15／30秒）、新着位置（下／上）を設定できます。表示時間は操作画面の受信時刻から数えます。出力を開き直しても期限は延びません。雑談画面の履歴・ユーザー管理・読み上げは残り、制限を緩めると保持中の履歴から条件に合う投稿が再表示されます。履歴件数より多くは出せず、枠に収まる件数は文字と枠の大きさにも依存します。デザインプレビューは10件のサンプルで件数と新着位置を確認でき、サンプルは時間で消えません。

## ローカルフォルダーの素材を使う

1. OSのファイル管理画面で、素材を`customization/styles/`または`customization/images/`へコピーします。
2. 「配信デザイン」→「ローカルのカスタマイズファイル」で「一覧を更新」を押します。
3. CSSは「スタイル（CSS）」で選び、「選んだスタイルを適用」を押します。
4. 画像は「画像」で選び、「画像を使う場所」を「立ち絵」または「名前・コメントの背景」にして、「選んだ画像を適用」を押します。選択しただけでは適用しません。

| 素材 | フォルダー | 対応形式と上限 |
| --- | --- | --- |
| CSS | `customization/styles/` | UTF-8の`.css`、100,000バイト以内 |
| 立ち絵・読み上げ背景 | `customization/images/` | `.png`・`.jpg`・`.jpeg`・`.webp`・`.gif`、各524,288バイト以内（512KiB） |

対象は各フォルダーの直下にある通常のファイルだけです。サブフォルダーを検索せず、シンボリックリンクも読み込みません。SVG・HTMLや任意のファイルは読み込み対象ではありません。画像はブラウザで読み込めることを確認してから適用します。隠しファイル、Windowsで使用できない名前（例：`CON.css`）、末尾が空白やピリオドの名前も対象外です。CSSは手動入力・ファイル読み込みと同じ検証を行い、[CSSの公開契約](#cssの公開契約)の範囲でだけ適用します。

ファイルを追加・名前変更・編集した場合は一覧を更新し、必要な素材を選んで適用し直してください。自動監視・自動反映はしません。アプリの画面からフォルダー内のファイルを作成・編集・削除する機能はありません。

### 適用後はブラウザに内容を保存

適用したCSS本文・画像データはブラウザのlocalStorageに保存します。ファイルパスを保存して毎回読み直す方式ではありません。

- 同じブラウザプロファイル・同じオリジンで開けば、再読み込み・再起動後も適用内容を使います
- 元ファイルを編集しても、適用済みの内容は変わりません。一覧更新後に再適用してください
- 元ファイルを移動・削除しても、ブラウザに保存済みの内容は残ります
- 保存容量不足や保存拒否があると再起動後の維持はできません。表示されたエラーを確認し、素材を小さくするか手動バックアップを使ってください
- 別のブラウザ・別のポート・GitHub Pages版へは自動移行しません。移行には「設定のバックアップ」を使ってください

`customization/`は元ファイルの置き場で、ブラウザの設定保存場所ではありません。両方を残したい場合は、フォルダーのコピーと設定バックアップの両方を保管してください。新しいローカル配布版へ更新する場合も、自分の`customization/`だけを新しい版の同じ場所へコピーします。アプリ本体の標準ファイルは新しい版のものを使ってください。

## 音声クレジットの表示

ローカル版でVOICEVOX・COEIROINKを選ぶと、ホームのプレビューと雑談画面の読み上げ枠に、選択した声のクレジットを自動表示します。パネル・吹き出し・画像の各スタイルで表示し、読み上げ本文のスクロール領域とは別に配置します。読み上げ枠を非表示にしたり、極端に小さくしたり、別の枠を重ねるとクレジットも映らない場合があります。配信前にOBS側でも確認してください。見た目のリセットでは音声設定を変えず、クレジット表示も選択した声を引き継ぎます。各音声の追加条件は[READMEの読み上げ案内](../README.md)と音声側の利用規約を確認してください。

## 自由配置

「配信デザイン」の「画面の配置」で、ホームまたは雑談画面を選びます。
「画面を見ながら配置を変える」で選んだ画面を開きます。
枠の「移動」をドラッグし、「大きさ」をドラッグするとサイズを変更できます。
編集が終わったら、画面上の「完了して設定に戻る」を押します。通常表示では編集バーは表示しません。
矢印キーで移動、Shift＋矢印キーでサイズを変更できます。
「枠ごとに表示や位置を調整する」を開くと、枠の選択欄から横位置・縦位置・幅・高さ・重なり順・非表示を設定できます。
座標とサイズは画面の割合（%）で保存し、2%への吸着を切り替えられます。
ホームと雑談画面の配置は独立しています。「選んだ画面の配置を元に戻す」は選択中の画面を初期配置に戻します。
非表示にしたパネルも編集時には半透明で表示し、再表示できます。

接続設定やユーザー一覧の専用ページは従来の配置を使います。
ホームのユーザー管理パネルは自由配置できます。テーマCSSは専用ページやサイドバーにも適用できます。

## CSSの公開契約

「配信デザイン」の「詳しく見た目を編集する（CSS）」を開くと編集・適用できます。CSSファイルの読み込み・書き出しにも対応します。
Theme API 1のセレクターは次のとおりです。

| セレクター | 対象 |
| --- | --- |
| `.pokome-workspace` | 操作画面、サイドバー、ホームの配置領域、雑談画面 |
| `.pokome-panel[data-panel-type="comments"]` | ホームのコメント一覧 |
| `.pokome-panel[data-panel-type="now"]` | 読み上げプレビュー |
| `.pokome-panel[data-panel-type="reading"]` | 読み上げ設定 |
| `.pokome-panel[data-panel-type="moderation"]` | ユーザー管理 |
| `.pokome-panel[data-panel-type="header"]` | 雑談画面のタイトル・接続状態 |
| `.pokome-panel[data-panel-type="chat"]` | 雑談画面のコメント一覧 |
| `.pokome-panel[data-panel-type="speech"]` | 雑談画面の読み上げ |
| `.pokome-panel[data-panel-type="actor"]` | 立ち絵・ワイプ |
| `.pokome-panel[data-panel-type="footer"]` | 雑談画面のフッター |
| `.pokome-comment` | コメント1件 |
| `.pokome-comment__author` | コメントのユーザー名 |
| `.pokome-comment__body` | コメント本文 |

全セレクターは `.pokome-workspace` またはその子孫を指定してください。
通常ルールと `@media`、`@supports` に対応します。ネストした通常ルールは展開してください。
外部URL、画像URL、`@import`、`@font-face`、キーフレームはこの版では対応しません。
CSS本文の長さは100,000文字相当まで（JavaScriptの文字列長で判定）、手動の読み込みファイルは200,000バイトまでです。ローカルフォルダーから選ぶCSSファイルは100,000バイトまでです。ブラウザが解釈できない宣言は適用されません。

```css
/* Pokome Theme API: 1 */
.pokome-workspace {
  --pk-font-family: sans-serif;
  --pk-accent-color: #ffd19a;
}
.pokome-workspace .pokome-panel {
  background: #20232b;
  border: 1px solid #ffd19a;
  border-radius: 8px;
  color: #fff;
}
.pokome-workspace .pokome-comment__body {
  line-height: 1.6;
}
```

`--pk-font-family`、`--pk-text-color`、`--pk-accent-color`を提供します。
詳細な外観は公開セレクターに直接指定できます。位置・サイズはレイアウト編集で管理します。
既存のテーマや配信デザイン設定の上にCSSを適用します。
例外として、配信デザインの「コメント欄の見た目」で「テーマのまま」以外を選んだ項目（パネルの背景、本文・名前の色、縁取り、行間、間隔、区切り線、見出し）は、その設定が優先されます。CSSに`!important`を付けた指定よりも優先します。パネルの背景を白・黒にすると、文字の色が「テーマのまま」でもパネルに合った読みやすい色を使います。コメント欄をCSSで細かく指定する場合は、その項目を「テーマのまま」に戻してください。
配置を編集中は、画面上の完了ボタンがテーマの影響を受けない独立した領域に表示されます。
雑談画面はEscapeキーでも終了できます。

## 標準に戻す

- CSSだけを戻す：「追加した見た目を解除」で、追加CSSの適用を解除します。配信デザインの設定・画像・配置はそのままです
- 立ち絵だけを外す：「画像を削除」で登録画像を外します。表示方法の選択は保持するため、OBS用の空き枠として使う場合は「表示するもの」も「空き枠 / OBSで映像を重ねる」に切り替えてください。標準の立ち絵画像は同梱していません
- 読み上げ背景だけを戻す：「標準の背景画像に戻す」で、同梱の吹き出し背景へ戻せます
- 配置だけを戻す：「選んだ画面の配置を元に戻す」で、選択中のホームまたは雑談画面の配置だけを初期化します
- 見た目全体を戻す：操作画面の右下にある「見た目を標準に戻す」を押し、確認画面で「標準に戻す」を押します。CSS・立ち絵・読み上げ背景・配信デザインの設定（色・文字・配信タイトルなど）・両画面の配置を初期状態へ戻し、立ち絵の表示方法も標準の空き枠になります。接続先・音声・ユーザー管理設定は保持します。確認画面の「キャンセル」では何も変更しません

見た目全体のリセット操作は追加CSSの影響を受けない領域にあります。雑談モードでは表示しないため、「雑談モードを終了」またはEscapeキーで操作画面に戻ってから使ってください。どのリセットも元のCSS・画像ファイルを削除・上書きしません。ブラウザへ保存したカスタマイズを残したい場合は、リセット前に「設定のバックアップ」を保存してください。

## 保存と共有

配置は `pokome-workspace-v1`、CSSは `pokome-theme-v1` というlocalStorageキーに保存します。
ブラウザが保存を拒否した場合は通知し、ファイルへの書き出しで保管できます。
配置JSONだけ、CSSだけ、または「見た目と配置をファイルに保存」でデザインJSONを共有できます。

```json
{
  "manifest": { "format": "pokome-design", "version": 1, "themeApi": 1 },
  "theme": ".pokome-workspace { --pk-accent-color: gold; }",
  "layout": { "version": 1, "home": null, "talk": null }
}
```

配置の `null` は初期配置です。自由配置では各画面の `panels` に全パネルの
`x`, `y`, `w`, `h`, `z`, `hidden` を保存します。
位置・サイズは画面内に収め、幅・高さは5〜100%、重なり順は0〜99に制限します。
未知のデータは取り込みません。対応しないバージョンや不足したパネルは拒否します。

共有ファイルに接続先、コメント履歴、ユーザー管理データは含めません。
「見た目と配置をファイルに保存」の共有対象はCSSと配置です。立ち絵・背景画像、既存の配信タイトルや読み上げ設定、作者情報、画像・フォントのアセット同梱は共有対象に含まれません。

画像や配信デザインも含めて自分の環境を移す場合は、「接続設定」の「設定のバックアップ」を使います。こちらには接続先・音声・ユーザー管理などの設定も含まれるため、他の人へ渡す前に内容を確認してください。フォルダーから適用した内容も保存対象ですが、`customization/`内の未適用ファイルや元ファイルそのものをまとめる機能ではありません。

ブラウザCSSOM・画面操作の検証テストはPlaywrightと対応ブラウザを使います。インストール済みのPlaywrightと、同梱ブラウザまたはLinux／Windowsの対応ブラウザを自動検出します。必要に応じて`PLAYWRIGHT_MODULE`にPlaywrightモジュールのパス、`BROWSER_EXECUTABLE`にブラウザの実行ファイルを指定できます。利用できる環境が見つからない場合はブラウザを使うテストをスキップします。

ブラウザの起動が実行環境の制限で禁止されている場合は、`SKIP_BROWSER_TESTS=1`でサーバー・モデルのテストだけを実行できます。これは画面検証の合格を意味しません。対応環境でブラウザテストを別途実行してください。

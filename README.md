# ぽこめ Reader

Twitch・Kickのコメント表示・音声読み上げ・ローカルのユーザー管理アプリ。

## 動作画面

サンプルコメントを使って、ローカル開発版で読み上げ中の画面を撮影しています。Windows配布版ではKickのボタン・接続設定は表示されません。

### 通常画面

コメント一覧、読み上げプレビュー、読み上げ設定、ユーザー管理をまとめて操作できます。

![通常画面：サンプルコメントの一覧と読み上げ中のプレビュー](docs/screenshots/normal.jpg)

### 雑談モード

設定を隠し、コメント、読み上げ中の内容、立ち絵・ワイプ用のスペースを表示します。画像はコメント8件・標準背景画像の設定例です。

![雑談モード：コメント8件、読み上げ中の吹き出し、OBS用の空き枠](docs/screenshots/talk.jpg)

## 提供している版

以前のGitHub Pages版（devunit47.github.io）は終了しました。今は、PCで動かす次の2つの版だけを提供しています。旧ページには移転の案内だけを表示します。旧ページで保存した設定は、ローカル版へ自動では引き継がれません。旧ページの「設定のバックアップ」で保存したファイルがあれば、ローカル版の「設定のバックアップ」から復元できます。

移転した理由は次の2つです。

- OBSへの取り込み、VOICEVOX・COEIROINKとの連携、PCのフォルダーからの素材の読み込みなど、ローカル版でしか使えない機能が増え、ブラウザ版との差が大きくなったため。
- YouTube・Kickなど今後追加したいサービスへの接続には、PC上で動くサーバーが必要になり、ブラウザ版のままでは対応できないため。

| 機能 | Windowsローカル配布版 | ローカル開発版 |
| --- | --- | --- |
| Twitchコメント表示・ブラウザ標準音声 | ○ | ○ |
| Kick接続 | × | ○ |
| VOICEVOX・COEIROINK v2 | ○（同じPCで別途起動） | ○（同じPCで別途起動） |
| 配色・配置・CSS・立ち絵・読み上げ背景の変更 | ○ | ○ |
| 画像・CSS・全比率の配置をまとめたデザインプリセット | ○ | ○ |
| ファイル選択画面からCSS・画像・デザインを読み込む | ○ | ○ |
| アプリ横の専用フォルダーを一覧表示してCSS・画像を選ぶ | ○ | ○ |
| ブラウザへの設定保存・手動バックアップ | ○ | ○ |

Kickは公式API以外の接続方式のため、開発版だけで有効にしています。配布版への追加は、Twitch版の完成後に検討します。

## ローカルで動かす（Twitch・Kick／開発版）

1. Node.js 20以上を用意します。
2. このリポジトリをダウンロードして展開するか、Gitでクローンします。
3. `package.json`があるフォルダーでターミナルを開き、次のコマンドを実行します。外部パッケージのインストールは不要です。

   ```sh
   npm start
   ```

4. ブラウザで [http://localhost:5173](http://localhost:5173) を開きます。
5. 上部のTwitchボタン右側の歯車から接続設定を開き、Twitchのチャンネル名を入力して接続します。
6. Kickを使う場合は、Kickボタン右側の歯車から接続設定を開き、Kickのチャンネル名を入力して接続します。

Twitch・Kickは同時に接続できますが、チャットは統合しません。上部のボタンで表示を切り替え、表示中のサービスだけを読み上げます。接続に成功したチャンネル名はサービス別に保存され、次回の入力欄に復元されます。次回も接続操作は必要です。

利用中はターミナルを開いたままにしてください。終了するときはターミナルで`Ctrl+C`を押します。Kickの接続にはこのローカルサーバーが必要なので、`index.html`を直接開く方法では利用できません。

## GitHub Pagesの移転案内（開発者向け）

GitHub Pagesには、アプリではなく静的な移転案内（`pages/index.html`）だけを公開します。古いURL（`/output.html` など）を開いた人にも同じ案内を表示するため、`404.html` にも同じ内容を置きます。Actionsの「Publish moved notice to GitHub Pages」を手動で実行すると更新されます。案内ページにはスクリプト・外部の読み込みを入れません。

### 接続とサービスの切り替え

- 「接続設定」の専用入力欄で、Twitch・Kickそれぞれのチャンネルに接続します。同時接続でき、片方の切断・再接続はもう片方に影響しません。

- 上部には各サービスの接続状態とチャンネル名を表示します。接続済み（緑）、接続準備中（黄）、未接続・デモ（灰）、エラー・切断（赤）を文字と色で区別します。右端の歯車から、そのサービスの接続設定とチャンネル入力欄へ移動できます。

- **前回接続したチャンネル名は、接続成功時にサービス別にブラウザへ保存します。** 次回起動・再読み込みで各入力欄に復元します。未接続の入力や接続失敗で前回の値を上書きしません。切断しても保存値は残ります。自動接続・自動再接続は行いません。

- 上部のTwitch・Kickボタンで表示するサービスを切り替えます。統合チャットはなく、コメント履歴・受信数・初コメント判定・検索・ユーザー設定はサービスごとに独立しています。

- 初期表示は各サービスのサンプルコメントです。「デモコメント追加」で表示中のサービスにだけ追加できます。接続開始時にそのサービスのサンプルと旧履歴を消去します。

### 音声の読み上げ

- コメントを選択して個別に読み上げたり、自動読み上げを有効にできます。読み上げ設定はサービスごとに保持し、自動読み上げは表示中のサービスだけが対象です。サービス切り替え時に再生と待ち行列を停止し、非表示サービスのコメントを後から読み上げることもありません。日本語音声はOS・ブラウザに依存します。読み上げ待ちは最大20件です。

- 自動読み上げは初期状態でONです。ON／OFFをTwitch・Kick別に保存し、次回起動時に復元します。起動時に並ぶサンプルコメントは読み上げません。

- ボイスはホームの「読み上げ設定」でOS・ブラウザに用意された日本語音声から選択します。Twitch・Kick別に保存します。選択した音声が環境にない場合は標準音声で読み上げます。配信に映す場合はOBSでアプリの画面と音声を取り込んでください。

- 読み上げ本文は初期値100文字、10〜500文字で設定できます。ユーザー名は別枠です。URL省略は初期状態で有効で、`http://`・`https://`・`www.`から始まるURLを取り除きます。URLだけのコメントは読み上げません。元のコメント表示は変更せず、プレビューには読み上げ用の本文を表示します。

- 「連投・コマンド対策」では同じユーザーの同じ読み上げ本文を30秒間省略（初期状態で有効）、`!`・`/`から始まるコマンドの省略（初期状態で無効）、ユーザーごとの読み上げ間隔（0〜60秒、初期値0で無効）を設定できます。同文省略と間隔制限は自動読み上げだけに適用し、手動の読み直しは制限しません。

- Nightbotと接続先チャンネル本人を読み上げない設定をそれぞれ用意しています（初期状態で有効）。表示名ではなくアカウント名で判定し、コメント一覧には表示します。自動・手動の両方の読み上げに適用します。

- 文字数・URL・連投・コマンド・ユーザー除外設定はTwitchとKick別にブラウザへ保存します。変更すると現在の読み上げと待ち行列を停止します。読み上げ方式はブラウザ標準・VOICEVOX・COEIROINK v2から選べます（追加方式はローカル版のみ）。

#### VOICEVOX・COEIROINKの声を使う（ローカル版）

1. [VOICEVOX](https://voicevox.hiroshiba.jp/)または[COEIROINK v2](https://coeiroink.com/)を公式サイトから入手して、同じPCで起動します。本体・音声モデルはこのアプリに同梱しません。
2. ホームの「読み上げ設定」→「読み上げ方式」で音声ソフトを選びます。
3. 取得された「音声」から話者・スタイルを選び、「音声テスト」で確認します。起動後や声を追加した後は「声を再取得」を押してください。

VOICEVOXは標準ポート50021、COEIROINK v2は50032へローカルサーバー経由で接続します。独自のポート設定・COEIROINK v1には対応しません。音量・速さ、読み上げ除外・待ち行列・停止はブラウザ標準音声と共通です。方式と選択した声はTwitch・Kick別に保存します。音声ソフト未起動・生成失敗時はエラーを表示し、別の声へ自動切り替えしません。

選択した声の名前を音声ソフトから取得し、ホームの読み上げプレビューと雑談画面の読み上げ枠に `VOICEVOX:キャラクター名`／`COEIROINK:音声名` を自動表示します。スタイルを切り替えても同じ話者名を使い、音声・方式・サービスの切り替えに追従します。再生中と終了後の表示には、その音声を読み上げたときのクレジットを保持します。ブラウザ標準ではこのクレジットを表示しません。

名前は保存済みの表示ラベルから推測せず、再読み込み・設定復元後に音声ソフトから再取得します。取得前・失敗時・名前の情報がない場合は `VOICEVOX:音声名未取得` などと表示するため、「声を再取得」を押して配信前に確認してください。設定バックアップには方式・声のIDを保存し、取得した名前や生成音声は含めません。

自動表示だけで各音声の利用条件をすべて満たすとは限りません。追加の表記条件・利用可能な範囲は各音声の規約を確認し、OBSでクレジットが隠れたり切れたりしていないかも確認してください。[VOICEVOXのクレジット案内](https://voicevox.hiroshiba.jp/qa/)・[VOICEVOXの利用規約](https://voicevox.hiroshiba.jp/term/)・[COEIROINKの利用規約](https://coeiroink.com/terms)

### コメントとユーザーの管理

- 「設定」ページでリストに保持するコメント数を1〜300件に設定できます（初期値300件）。上限を超えると古いコメントを削除します。雑談画面の表示件数は枠と文字サイズに応じて変わります。配信出力の件数・時間制限は履歴とは別に設定できます。雑談画面のコメント欄にある＋／−で16〜28pxの文字サイズを調整・保存できます。枠に収まらないコメントはスクロールして確認できます。

- コメントはサービスごとに設定した件数（初期値300件、1〜300件）をメモリに保持し、ページを閉じると消えます。初コメントはそのサービスへの接続セッションでの初登場です。

- ユーザー名・コメントをクリックすると、ユーザーを非表示・このコメントを非表示・読み上げ除外のメニューが開きます。「このコメントを非表示」はその1件だけに適用され、ページを閉じると履歴と一緒に消えます。「ユーザーを非表示」「読み上げ除外」はサービス別にこのブラウザに保存され、「ユーザー管理」で解除できます。同じユーザー名でも他サービスには影響しません。旧バージョンのユーザー設定はTwitchだけに引き継ぎます。各サービス上のBAN・タイムアウトとは別です。

### 雑談モードとOBSへの取り込み

- メインメニューの「雑談モード」で配信に映す画面へ切り替えます。設定・ユーザー管理・検索などを隠し、チャット、実際に読み上げ中のコメント、装飾、配信者用スペースを表示します。Twitch・Kickのコメントは混在せず、表示中のサービスのみ読み上げます。右上に常時表示する「雑談モードを終了」で操作画面に戻れます。Escapeキー・ブラウザの「戻る」でもホームに戻れます。接続設定などのダイアログ表示中は、Escapeキーでダイアログを閉じます。雑談モードの「自動読み上げ ON／OFF」はホームの設定と連動し、OFFにすると再生と待ち行列を停止します。接続状態を押すと画面を移動せず接続設定を開けます。

- 配信者用スペースにOBSで顔映像・Vtuberモデルを重ねて配置できます。アプリにはカメラ起動・取得機能はありません。立ち絵画像を表示することもできます。

#### 配信出力（OBS用）

「配信デザイン」→「配信出力（OBS用）」で、配信に映す画面だけを別に開けます。ボタン・案内文・通知は映りません。チャットの接続と読み上げは操作画面が行い、配信出力は表示だけを担当します（出力から音は出ません）。非表示にしたユーザー・コメントは配信出力に送りません。

配信出力の表示件数（標準は制限なし／1～30件）・表示時間（時間では消さない／5／15／30秒）・新着位置を「コメント一覧」で設定できます。履歴と読み上げは保持します。詳しくは[表示件数と表示時間](docs/customization.md#配信出力の表示件数と表示時間)を参照してください。

| 取り込み方 | 背景 | 向いている使い方 |
| --- | --- | --- |
| ① ウィンドウキャプチャ | テーマの背景、またはクロマキー用の単色（緑・マゼンタ・青） | 普段のブラウザで操作したまま取り込む |
| ② OBSのブラウザソース | 透明 | 顔映像やゲーム画面の上に文字をきれいに重ねる |
| 雑談モード（従来） | テーマの背景 | 操作画面をそのまま映す |

**① ウィンドウキャプチャ**

1. 背景と出力の大きさを選び、「配信出力ウィンドウを開く」を押します。押し直しても、ウィンドウは1つのままです。
2. OBSに「ウィンドウキャプチャ」を追加して出力ウィンドウを選び、キャプチャ方式は「Windows 10（1903以降）」にします。
3. 上端のアドレス表示は、ソースをAltキーを押しながらドラッグして切り取ります。
4. 単色の背景にした場合は、ソースに「クロマキー」フィルターを追加し、同じ色を選びます。文字の縁取り・影・半透明の枠には背景色がにじむことがあります。

出力ウィンドウを最小化したり、ほかのウィンドウで完全に隠したりすると、表示が止まることがあります。

**② OBSのブラウザソース**

OBSは普段のブラウザと保存先が別のため、操作画面もOBSの中で開きます。

1. 「操作画面のURL」を、OBSの「ドック」→「カスタムブラウザドック」に追加します。チャンネルの接続や見た目の設定は、このドックで行います。
2. シーンに「ブラウザ」ソースを追加し、「出力のURL」と大きさ（例：1920 × 1080）を入力します。
3. 読み上げの音はドックから鳴ります。配信に音が入っているか、OBSの音声ミキサーで確認してください。

どちらの方法でも、操作画面は1つだけ開いてください。複数開いている場合は、配信出力の欄に警告を表示します。

- 雑談画面で文章にマウスを重ねると鉛筆ボタンが表示されます。タイトル（60文字）、ひとこと・画面下の文章（100文字）、読み上げ枠の見出し（40文字）をその場で編集し、「保存」で反映します。空欄でも鉛筆ボタンから再編集できます。

### 画面の配置とデザイン

- 「配信デザイン」の「デザインを編集」で開くデザインエディタで、4つのテーマ、アクセント色、文字サイズ、装飾の有無、読み上げ枠・立ち絵の見た目と画像、出力の大きさ、テーマCSSを変更できます。「適用」でアプリの`customization/current/`フォルダーに保存します。画像はPNG・JPEG・WebP・GIFの1枚20MB・1600万画素以内に対応します。適用すると、開いている配信出力（OBSのブラウザソースを含む）や別のタブにもすぐ反映します。

- デザインエディタの「コメント欄」で、一覧全体のパネル背景、投稿ごとの丸い背景と不透明度、本文と名前の色、文字の縁取り、行間、本文の最大行数、コメント同士の間隔、区切り線、見出しの表示を変更できます。「テーマ標準」「縁取り文字だけ」「白パネル」「半透明の暗パネル」「本文だけ高密度」「丸いチップ（本文2行）」から、まとめて切り替えることもできます。プリセットは配置・文字サイズ・表示件数を変えません。雑談画面・プレビュー・配信出力に同じように反映します。

- コメントの文字サイズは16〜64pxで設定できます（標準20px）。テーマCSSに文字サイズの指定がある場合は、その指定が優先されます。読み上げ本文の文字サイズは従来の16・22・28・32pxのままです。本文の行数制限は表示だけに適用し、履歴や読み上げの本文は切りません。「1行コンパクト」にも明示した行数を優先します。

- デザインエディタの「立ち絵」の「立ち絵の枠・背景・キャプション」で「すべて消す」を選ぶと、枠線・背景・角丸・枠内の飾り・キャプションをまとめて消せます。画像の大きさと配置は変わりません。

- 「デザインを編集」で開くデザインエディタで、配色・文章・コメント欄・読み上げ・立ち絵の見た目、テーマCSS、雑談画面に追加する文字・画像（最大20個）を、配信画面を見ながら1つの下書きで編集できます。追加した項目はドラッグ／矢印キーで独立して移動・サイズ変更し、文章・色・文字サイズ・重なり順・非表示を調整できます。「適用」で保存、「変更をすべて破棄」で編集前に戻します。画像は1枚20MB・1600万画素以内です（合計の上限はありません）。接続・読み上げ・コメント保持数は変更しません。従来の下側の設定は即時反映のままです。
- 「配信デザイン」の「画面の配置」から、ホーム・雑談画面の枠を移動・サイズ変更・非表示にできます。配置は画面ごとに保存します。雑談画面（配信に映す画面）の配置は16:9・9:16・4:3の比率ごとに`customization/current/`へ、ホームの配置はこのブラウザに保存します。雑談画面は「編集する比率」を選んで、その比率の枠の中で編集します。雑談モードは「出力の大きさ」の比率、配信出力は自分の大きさにいちばん近い比率の配置を使います。CSSファイルの読み込み・保存もできます。CSSを直接編集する機能は「詳しく見た目を編集する（CSS）」にあります。[カスタマイズ仕様](docs/customization.md)を参照してください。

#### ローカルフォルダーからCSS・画像を選ぶ

ローカル版は、アプリと同じ場所に次の専用フォルダーを自動で用意します。開発版では`package.json`がある場所、Windows配布版では`Start.cmd`がある場所です。

```text
customization/
  styles/   ← 自作・配布されたCSS
  images/   ← 立ち絵・読み上げ枠の背景画像
  current/  ← 適用中の見た目（アプリが書き込む。design.json と images/）
  presets/  ← 名前付きのデザインプリセット（idごとのフォルダー）
```

1. エクスプローラーなどで、CSSを`customization/styles/`、画像を`customization/images/`へコピーします。
2. 「配信デザイン」→「ローカルのカスタマイズファイル」で「一覧を更新」を押します。
3. CSSは「スタイル（CSS）」で選び、「選んだスタイルを適用」を押します。画像は「画像」で選び、「画像を使う場所」を「立ち絵」または「名前・コメントの背景」にして、「選んだ画像を適用」を押します。選択だけでは切り替わりません。

CSSはUTF-8の`.css`（1,000,000バイトまで）、画像はPNG・JPEG・WebP・GIF（各20MiB／20,971,520バイトまで、1600万画素以内）です。各フォルダーの直下に置いてください。サブフォルダー内のファイルやシンボリックリンクは読み込みません。CSSには[指定のセレクターと制限](docs/customization.md#cssの公開契約)があります。CSSから画像URLを指定せず、画像は専用の選択欄から適用してください。

適用するとファイルの内容を`customization/current/`にコピーして保存します。元ファイルへの参照ではないため、元ファイルを移動・削除しても適用済みの見た目は残ります。ブラウザやポートを変えても、同じアプリのフォルダーなら同じ見た目になります。元ファイルを編集したときは、一覧を更新してもう一度適用してください。自動追従はしません。アプリが書き込むのは`customization/current/`と`customization/presets/`で、`styles/`・`images/`の元ファイルは書き換えません。

「配信デザイン」の先頭から、画像・CSS・すべての比率の配置をプリセットに保存できます。読み込みは比率を切り替えてプレビューで確認し、適用すると今のデザイン全体を置き換えます。キャンセルでは変わりません。保存先は`customization/presets/<id>/`で、別の環境へ移すときはこのフォルダーを丸ごとコピーします。上書き保存・名前変更・削除・標準へ戻す・手置きフォルダーの一覧更新もできます。詳しくは[プリセットの使い方](docs/customization.md#デザインのプリセット)を参照してください。

プレビューの「この比率の立ち絵画像の配置」で、100〜200%の拡大・位置合わせ・微調整・枠からのはみ出しを比率ごとに試せます。追加画像も幅・高さ200%まで画面外に置けます。変更は「適用する」でまとめて保存します。[画像配置の説明](docs/customization.md#立ち絵画像と追加画像の配置)を参照してください。

#### 標準の見た目に戻す

標準の外観・初期設定・吹き出し背景は、アプリ本体の`style.css`、`src/shared/theme.js`、`src/shared/studio.js`、`speech-background.svg`に分けて保持します。`customization/`は利用者の素材専用で、標準素材を入れたり上書きしたりしません。カスタマイズのためにアプリ本体のファイルを編集する必要はありません。

デザインエディタでは、CSSだけの解除、立ち絵の削除、標準の読み上げ背景へ戻す操作をそれぞれ下書きとして試せます。操作画面の右下にある「見た目を標準に戻す」で確認後に「標準に戻す」を押すと、追加した文字・画像、CSS・配信デザインの設定とホーム／雑談画面の配置をまとめて戻し、立ち絵も標準の空き枠になります。接続先・音声・ユーザー管理設定は保持し、`styles/`・`images/`内の自分のファイルは削除しません。残したい見た目は、先にプリセットに保存しておいてください。プリセット欄の「標準へ戻す」は配信デザイン全体を戻し、ホームの配置は変えません。

### 読み上げ枠の表示とスタイル

- 「いま、届いた声」は読み上げ終了後も5秒間残します。次の読み上げが始まると新しいコメントに切り替わり、停止・サービス切り替え時は表示をクリアします。

- 枠の高さは「画面の配置」で調整できます。長い本文は枠内でスクロールできます。狭い雑談画面ではコメント・読み上げ・立ち絵を縦に並べ、画面全体をスクロールして確認します。

- 読み上げ枠は立ち絵・OBSスペースの上に配置し、チャットは隣の列の高さ全体を使います。枠の位置や大きさは「画面の配置」で自由に変更できます。読み上げ枠の見出し（40文字まで）は雑談画面の鉛筆ボタンで変更・保存できます。本文の文字サイズ（16・22・28・32px）は「配信デザイン」で変更できます。

- 読み上げ枠の見出しにスピーカーアイコンを表示し、読み上げ中は装飾用の波形が動きます（音量・音声波形とは同期しません）。状態は「読み上げ中／待機中」で表示します。終了後の本文保持中は待機中になり、波形が停止します。OSの動きを減らす設定ではアニメーションを停止します。

- デザインエディタの「読み上げ」で枠のスタイルを「セリフの吹き出し」にすると、立ち絵・ワイプ枠へ向くしっぽ付きの背景になります。背景色を変更・保存でき、本文の白黒は背景の明るさに合わせて切り替わります。通常のパネルにも戻せます。

- 「背景画像」は名前・コメント本文だけに画像を敷き、見出し・波形・状態表示は画像の外に表示します。標準の吹き出し画像を同梱し、新規設定の初期スタイルに使用します。PNG・JPEG・WebP・GIFの20MB・1600万画素以内の画像に差し替え、本文の文字色も変更できます。画像は`customization/current/`に保存し、外部へアップロードしません。「標準の背景画像に戻す」で復元できます。既存のパネル・吹き出し設定は維持します。

### 接続方式と利用上の制約

接続は外部通信が必要です。認証、コメント送信、各サービス上でのモデレーションは未実装です。Webフォントが使えない場合はシステムフォントで表示します。

Kickは公開チャット用Pusher WebSocketを読み取り専用で購読します。チャンネル名からチャットルームIDを取得するため、localhostサーバーがKickのチャンネル情報APIへ問い合わせます。公開WebSocketは公式Webhook APIとは別の接続方式で、Kick側の仕様変更やアクセス制限で利用できなくなることがあります。公式Webhook APIの利用にはアプリ登録・認証・外部から到達可能な受信サーバーが必要なため、今回は導入していません。取得・購読・通信の失敗は画面に表示します。

接続方式の参考: [TwitchのWebSocket接続に関する告知](https://discuss.dev.twitch.com/t/decommission-of-non-secure-websocket-connections-to-twitch-irc-servers/64142)、[匿名接続に関する開発者フォーラム](https://discuss.dev.twitch.com/t/can-i-use-wss-irc-ws-chat-twitch-tv-with-justifan/63732)。匿名接続はサービス側の変更で使えなくなる可能性があります。

Kick接続の参考: [Pusherプロトコル](https://pusher.com/docs/channels/library_auth_reference/pusher-websockets-protocol/)、[公開チャット接続の実装例](https://gist.github.com/Linch1/861902c8a85977b4dbcb562966b65bed)、[Kick公式Webhook仕様](https://github.com/KickEngineering/KickDevDocs/blob/main/events/event-types.md)。2026年10月1日に公開WebSocketの購読成功とサービス別接続先の復元を実通信で確認しています。

## Windowsのローカル配布版

[GitHub Releases](https://github.com/devunit47/pkm-comment-reader/releases)にある `pokome-reader-v…-windows-x64.zip` をダウンロード・展開して、`Start.cmd` をダブルクリックします。対応はWindows x64です。Releaseがまだない場合は、以下の手順で開発者が生成できます。

開発者がWindows上で `npm run build:local` を実行すると、Node.js同梱のTwitch専用 `dist-local/` が生成されます。配布版ではKickの表示・接続を無効にし、Kick用モジュールを含めません。開発版はTwitch・Kick対応のままです。フォルダー全体を配布し、利用者は展開後に `Start.cmd` をダブルクリックします。Node.jsのインストールやコマンド入力は不要です。VOICEVOX・COEIROINKは別途起動してください。

ブラウザを閉じてもサーバーはバックグラウンドで動作し、PCを終了すると停止します。開発用は5173、配布版は5174を使うため同時に起動できます。起動時にポート5174を確認し、このアプリが起動済みならブラウザだけを開きます。配布物にはNode.jsのライセンスを同梱します。Windowsの警告表示や組織の実行制限には別途対応が必要です。

開発サーバーのポートを変更する場合は、PowerShellで `$env:PORT = "5175"` を設定してから `npm start` を実行します。接続先・音声などブラウザの保存設定はポートごとに独立します。見た目は`customization/`に保存するので、ポートを変えても変わりません。

### ローカル配布版を更新するとき

まず起動中の旧版ローカルサーバーを終了してください。開発版はターミナルで`Ctrl+C`、Windows配布版はPCの再起動で確実に停止できます。ブラウザを閉じるだけでは旧版サーバーは止まりません。旧版を停止してから新しい版の`Start.cmd`を実行してください。

新しいZIPは別のフォルダーに展開し、古い版の`customization/`を新しい版の同じ場所へコピーしてください。利用者の素材は新しい配布物へ自動では引き継がれません。標準素材を戻せるよう、古い`style.css`などのアプリ本体は新しい版へ上書きしないでください。

適用済みの見た目は`customization/current/`にあるので、`customization/`をコピーすれば新しい版でもそのまま使えます。接続先・音声などはブラウザの保存データなので、同じブラウザプロファイルと同じオリジン（例：`http://localhost:5174`）を使う限り引き継がれます。ブラウザ・ホスト名・ポートを変える場合やサイトデータを消す場合に備えて、更新前に「設定のバックアップ」も保存してください。

見た目は今回からversion 3で保存します。version 2は従来の見た目で読み、読むだけでは変更しません。更新前にアプリを終了し、`customization/`全体（少なくともcurrentとpresetsをdesign.jsonとimagesごと）を別の場所へ退避してください。「設定のバックアップ」には見た目と画像が入りません。

古い版に戻すなら**v0.3.1以降**を使い、新版の保存先ではなく退避したversion 2のフォルダーを使ってください。v0.3.0以前では操作画面を開くだけでも24時間より古いcurrent画像が消え、設定変更や標準復帰で原本が上書きされる場合があります。v0.3.1以降は読めない原本と画像を保護しますが、version 3非対応版では表示・編集できません。versionだけを2に書き換えても互換性は戻りません。詳しくは[保存形式と更新時の退避](docs/customization.md#保存形式と更新時の退避)を参照してください。

### GitHub Releaseの自動作成（開発者向け）

変更をコミット・Pushした後、`v1.0.0` のようなバージョンタグを作成してPushすると、「Release Windows local version」が検証・Windows版ビルド・ZIP作成・Releaseへの添付を自動で行います。通常のブランチPushではReleaseを作成しません。

```sh
git tag v1.0.0
git push origin v1.0.0
```

次回は未使用のバージョン番号を指定してください。`v1.0.0-beta.1` のようなタグはプレリリースになります。公開済みReleaseは上書きしません。更新時は新しいタグを使用してください。ZIPとSHA-256チェックサムを添付します。Node.jsは同梱ライセンスと一致する24.19.0に固定しています。更新時は `NODE-LICENSE.txt` も同じバージョンに更新してください。GitHub Pagesの移転案内は別の手動ワークフローで更新します。

masterへのPush・Pull RequestでCIが構文チェックとテスト、Windows配布版のビルドを実行します。構文チェックは生成物・依存パッケージを除く全JavaScript（テストを含む）を対象にします。

配布版のポートも環境変数 `PORT` で変更できます。未指定時は5174です。展開したフォルダーでPowerShellを開き、`$env:PORT = "5175"; .\Start.cmd` を実行してください。WindowsのSmartScreenやウイルス対策ソフトが警告する場合があります。

バックアップの復元に失敗した場合は、適用途中の設定を消して元の設定への書き戻しを試みます。書き戻しも失敗した場合はエラーを表示します。バックアップファイルは復元後の確認が済むまで保持してください。
